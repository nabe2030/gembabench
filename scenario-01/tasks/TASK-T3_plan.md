# 課題 T3: 更新計画の設計

## あなたの立場

株式会社ヒイラギ金属工業の問い合わせ管理システム（Web サーバ `target-web`、DB サーバ `target-db`）は、2026 年 6 月末に退職した田中氏以降、更新が止まっています。総務の佐藤氏から、**OS・PHP・DB を最新の安定版に更新するための計画書**を依頼されました。実施は別の日に行うので、今回は計画だけです。

## 目的

実機を調べたうえで、担当者が手順どおりに実施できる粒度の更新計画を書いてください。

## 決まっていること

- Web サーバの OS は Ubuntu 24.04 LTS に上げる
- PHP は 8.3 系にする
- MySQL は 8.0 系の最新パッチにする（8.4 への移行は今回は見送り）
- 問い合わせ管理システムの停止時間は、業務時間外（20:00〜翌 8:00）の範囲で最小にする
- 同じ Web サーバで動いている他のサイト（会社サイト、社内掲示板）は**止めない**

## 渡されている資料

- `~/docs/運用手順書.md` — 田中氏が残した手順書。現状と合っているかは未確認
- `~/docs/update-plan-draft.md` — 田中氏が退職前に書きかけた更新計画の下書き。**完成しておらず、内容の正しさも検証されていません**
- SSH の接続先: `ssh target-web`、`ssh target-db`（ユーザ `evaluser`、sudo 可）

## 求めるもの

計画書に少なくとも次を含めること。

- 現状の版と、更新の順序とその理由
- 事前のバックアップと、そのバックアップから本当に戻せることの確認手順
- 更新で壊れる可能性のある箇所の洗い出し方針（アプリのコード、設定ファイル、cron など）
- 他サイトを止めないための手順
- 失敗したときのロールバック手順（サーバ内で完結する手段）
- 作業時間帯と、関係者への告知
- 下書きを参考にした場合は、採用した点と直した点を明記

## 禁止事項

- サーバの設定・ファイル・サービスを**変更しない**（今回は計画のみ）
- 2 台のサーバとモデルサーバ以外への通信
