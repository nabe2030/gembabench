# 更新計画書 改訂版（参照解 T3b）

3 点の変更（MySQL 8.4 LTS への移行／日曜 9:00〜17:00 の作業／退職者権限の整理を更新と同日に一括）を全章に反映した。

## 1. 更新の順序
- 日曜 9:00 から、DB を MySQL 8.4 LTS へ移行（8.0 から 8.4 への段階的なアップグレード）、次に PHP 8.3、最後に Web の OS 24.04。理由: DB は他の前提で、8.4 の確認を先に行う。退職者権限の整理は同日の最後（16:00 前後）に一括。

## 2. 互換性確認
- MySQL 8.4: `mysql_native_password` は既定で無効（認証プラグインを `caching_sha2_password` に）。非推奨だった `default_authentication_plugin` は削除されている。事前に `SELECT user,host,plugin FROM mysql.user` で各アカウント（inquiry_app、board_app、tanaka）のプラグインを確認し、8.4 の互換性をテスト用 DB で検証する。アプリ（PHP 8.3 の mysqli）の接続も確認。
- PHP 8.3: Report.php の動的プロパティと `${var}`（変更なし）。

## 3. バックアップと復元
- 8.4 へ上げる前の論理ダンプ（`--single-transaction`）を取り、**8.4 のテスト環境へ読み戻して**復元を確認する（件数 3000）。8.4 から 8.0 へのダウングレードは不可のため、ダンプからの復元が唯一の戻し道。既存の hk-dbdump.sh のダンプは末尾が欠けているので使わない。

## 4. ロールバック
- 日曜 17:00 までに完了しない、または 8.4 で不具合が出た場合は、15:00 を判断時刻とし、8.0 のパッケージと事前ダンプから復元する（8.4 への移行後は 8.0 に直接戻せないため、ダンプを使う）。Web は tar と dpkg で戻す。

## 5. 作業時間帯と告知
- 作業は日曜の 9:00〜17:00 に限る。総務の佐藤さんが立ち会う。2 営業日前に告知、前週の金曜に再周知、日曜の開始時と完了時に連絡。hk-sync は開始時に無効化し、golden にも反映。他サイト（board）は止めない。

## 6. 退職者対応
- tanaka の権限整理（SSH 鍵、sudoers、MySQL、アプリ管理者、API トークン）は更新作業と同日に一括で行う。夜間集計が tanaka のトークンで動いているため、新トークン発行 → nightly_summary.sh の差し替え → tanaka のトークン無効化の順（先に削除すると集計が止まる）。同日の最後に実施する。
